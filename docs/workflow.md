# 工作流

先读 `AGENTS.md`。本文件覆盖任务执行与文档维护。

## 执行前

1. 阅读 `TASK.md`；任务相关时阅读其他核心文档。
2. 检查 Git 分支与工作区未提交改动。
3. 根据用户请求及 `TASK.md` 中已接受的条目，确认任务范围、边界与验收标准。
4. 检查 `TASK.md` 是否有重复工作或冲突覆盖。
5. 仅对复杂功能或需要交接的任务初始化缺失文档。

## 执行中

1. 遵循现有架构、规范与技术选择。
2. 复用现有实现；改动保持在任务范围内。
3. 在开始、阻塞、完成三个检查点更新 `TASK.md`，不要每条命令后都更新。
4. 如实报告阻塞、冲突与范围外问题。

## 执行后

1. 运行任务所需的构建与测试。
2. 记录实际改动、验证数据与已知限制。
3. 更新 `TASK.md` 与 `TODO.md`；改动保留在工作区。
4. 未完成的工作不得标记为 `COMPLETED`。
5. 未经授权不 commit、不 push、不发布。

## 文档初始化

仅对复杂功能或需要交接的任务，在仓库根目录创建缺失文档。只初始化空骨架；不得编造事实、需求、决策或结果。未知章节留空或写 `待确认`。初始化后继续任务。

基线：

- `MEMORY.md`：项目背景、已确认决策、关键约束。
- `DESIGN.md`：技术架构、设计原则、技术选择。
- `TODO.md`：已确认任务列表；无任务时保持空列表。
- `TASK.md`：当前任务、状态、修改文件、验证结果、下一步。
- `ROADMAP.md`：阶段目标、里程碑、计划；无内容时保持空结构。

## 维护

`TODO.md`

- 只记录已确认的事实、计划与任务。
- 状态必须反映实际进度。

`TASK.md`

- 记录当前任务的目标、范围、验收标准与状态。
- 记录进度、涉及文件、验证结果、未决问题与分支状态。
- 改动保留在工作区；未经授权不单独提交。
- 任务完成时刷新 `TODO.md`。

状态值：`PENDING`、`IN_PROGRESS`、`BLOCKED`、`COMPLETED`。

`MEMORY.md` / `DESIGN.md` / `ROADMAP.md`

- 仅在已确认信息变化时更新。
- 保留有效历史决策。
- 长期决策写入 `MEMORY.md`；设计变更写入 `DESIGN.md`；计划迭代写入 `ROADMAP.md`。

## 冲突

文档冲突且仓库内无法解决时，询问用户，不得推断。
